Apertura

Actividad inicial — Del dato crudo a la decisión

15 min

Objetivo de aprendizaje

  • Reconocer, a partir de un ejemplo cotidiano, la diferencia entre "dato tal cual aparece" y "dato listo para responder una pregunta".
  • Conectar esa diferencia con el problema que resuelve la ingeniería de datos.

Dinámica: "Del recibo a la decisión"

Se proyecta o entrega en parejas un ticket de compra de supermercado y una captura de mensajes de WhatsApp donde un pequeño negocio registra sus ventas del día (nombre de producto, cantidad y precio escritos de forma libre e inconsistente).

  1. Cada pareja tiene 5 minutos para responder: "¿Cuál fue el producto más vendido esta semana?" usando solo esa información.
  2. Puesta en común (5 min): casi nadie puede responder con seguridad. Se anota en el tablero qué les faltó (orden, formato consistente, consolidación de varios días).
  3. Cierre de la dinámica (5 min): se nombra el problema — los datos existen, pero no están listos para usarse. Ese es el problema que resuelve la ingeniería de datos.

Introducción a la ingeniería de datos

¿Qué es la ingeniería de datos?

Es la disciplina que diseña y construye los sistemas que mueven, transforman y ponen a disposición los datos de forma confiable, para que otras personas o sistemas (analistas, científicos de datos, modelos de IA) puedan usarlos. En el ciclo de vida del dato — generación → recolección → almacenamiento → procesamiento → análisis/consumo — el ingeniero de datos trabaja sobre todo en la recolección, el almacenamiento y el procesamiento.

Bloque 2

ETL — Extract, Transform, Load

35 min

Objetivos de aprendizaje

  • Explicar qué ocurre en cada etapa de un proceso ETL, con ejemplos concretos.
  • Diferenciar ETL de ELT y cuándo conviene cada enfoque.
  • Seguir un mini-pipeline ETL guiado.
  • Identificar errores comunes y buenas prácticas al diseñar un proceso ETL.

Las tres etapas

  • Extract (extraer): obtener los datos de una o varias fuentes. Ej.: exportar las ventas de un sistema POS, consumir una API del clima, leer un CSV subido por un usuario.
  • Transform (transformar): limpiar, estandarizar, combinar y calcular. Ej.: unificar formatos de fecha, eliminar duplicados, convertir monedas, calcular totales por producto.
  • Load (cargar): escribir el resultado en un destino. Ej.: una tabla en un data warehouse o en una base de datos analítica.

ETL vs. ELT

EnfoqueCuándo transformaSe usa cuando…
ETLAntes de cargar, en un motor intermedioEl destino tiene poca capacidad de cómputo o hay reglas estrictas de calidad antes de guardar
ELTDespués de cargar, dentro del propio almacénEl destino es un warehouse cloud potente (BigQuery, Snowflake) y conviene guardar el dato crudo primero

Ejemplo guiado: mini-pipeline ETL

Partimos de un CSV de ventas con columnas desordenadas y construimos una tabla limpia de ventas por producto y día.

-- EXTRACT: datos crudos de la tabla de origen
SELECT * FROM ventas_raw;
-- fecha en texto, precio con símbolo "$", producto con espacios extra

-- TRANSFORM: limpieza y estandarización
SELECT
  TRIM(producto)                          AS producto,
  CAST(REPLACE(precio, '$', '') AS DECIMAL) AS precio,
  TO_DATE(fecha, 'DD/MM/YYYY')         AS fecha,
  cantidad
FROM ventas_raw
WHERE cantidad IS NOT NULL;

-- LOAD: resultado agregado al destino final
INSERT INTO ventas_limpias
SELECT producto, fecha, SUM(precio * cantidad) AS total_dia
FROM ventas_transformadas
GROUP BY producto, fecha;

Errores comunes y buenas prácticas

Errores comunes

  • No validar tipos de datos ni formatos.
  • Ignorar valores nulos o duplicados.
  • Mezclar la lógica de extracción con la de transformación.
  • No registrar logs ni manejar errores del proceso.

Buenas prácticas

  • Documentar y versionar cada paso del pipeline.
  • Diseñar cargas idempotentes (evitar duplicar al reprocesar).
  • Separar claramente extracción, transformación y carga.
  • Definir reglas de calidad antes de cargar al destino final.

Bloque 3

EDA — Análisis Exploratorio de Datos

30 min

Objetivos de aprendizaje

  • Explicar qué es el EDA y por qué se hace antes de modelar o reportar.
  • Aplicar técnicas básicas: estadísticas descriptivas, detección de nulos/outliers, visualizaciones típicas.
  • Seguir un ejemplo práctico corto de exploración sobre un dataset sencillo.

¿Qué es y por qué se hace primero?

El EDA es el proceso de examinar un dataset para entender su estructura, calidad y patrones antes de usarlo en un análisis o modelo. Evita que se construyan reportes o modelos sobre datos sucios o mal entendidos, algo que llevaría a conclusiones equivocadas.

Técnicas básicas

  • Estadísticas descriptivas: media, mediana, desviación estándar, conteos por categoría.
  • Valores nulos: calcular el porcentaje de datos faltantes por columna.
  • Outliers: detectarlos con el rango intercuartílico y boxplots.
  • Visualizaciones típicas: histogramas, boxplots, gráficos de dispersión, matrices de correlación.

Ejemplo práctico corto (pandas)

Sobre el mismo dataset de ventas ya limpio, exploramos su estructura antes de reportar:

import pandas as pd

df = pd.read_csv("ventas_limpias.csv")

df.head()              # primeras filas, vista rápida
df.describe()           # media, min, max, desviación estándar
df.isnull().sum()       # nulos por columna

# outliers con rango intercuartílico
Q1 = df["total_dia"].quantile(0.25)
Q3 = df["total_dia"].quantile(0.75)
IQR = Q3 - Q1
outliers = df[(df["total_dia"] < Q1 - 1.5*IQR) | (df["total_dia"] > Q3 + 1.5*IQR)]

df["total_dia"].hist()   # histograma de la distribución

Práctica integradora

15 min

Objetivo de aprendizaje

  • Aplicar, sobre un caso nuevo, lo visto en ETL y EDA de forma integrada.

Ejercicio

Se entrega a cada grupo un archivo de ventas de una tienda con problemas típicos: fechas en formatos distintos, precios guardados como texto, columnas duplicadas y algunos valores faltantes. En grupos pequeños (10 min):

  1. Identificar qué pasos de Extract, Transform y Load aplicarían y en qué orden.
  2. Listar al menos 3 pasos de EDA que harían antes de confiar en el dataset para un reporte.

Puesta en común de 5 minutos: cada grupo comparte un hallazgo de ETL y uno de EDA.

Materiales

Dataset de práctica con defectos intencionales Guía de trabajo en grupo

Entregable / verificación

  1. Lista escrita de pasos ETL por grupo, en orden.
  2. Lista escrita de al menos 3 pasos de EDA por grupo.
Nota para el instructor

Los tiempos son orientativos: la actividad inicial y el cierre son los más fáciles de ajustar si algún bloque se extiende. El dataset de ventas puede reutilizarse a lo largo de toda la clase (crudo en la actividad inicial y en ETL, limpio en EDA y en el cierre) para reforzar la idea de un único pipeline de principio a fin.
